# 來客活力與本機預錄迎賓：試作規格

> 狀態：本機試作整合完成；自動化測試與 Simulator 建置通過，待實機驗收
> 更新日期：2026-09-16

使用者在具體試作提案後要求「繼續」。本期採下列可調整規則，驗證完成
不等於實機音訊與正式客流設備已驗收。

## 來客訊號與去重

使用既有 camera／Vision pipeline 回傳的 usable-face presence，代表
「Lumi 面前出現客人」。第一次可用人臉訊號產生一個來客事件，持續有人時
不再計數。只有觀察到連續 3 秒無人，才允許下一次出現形成新事件。
短暫遮擋或轉頭不直接增加次數；相機故障／觀測不可用不視為無人，也不能
跨越故障時間推定持續無人。語音啟動失敗、重試、停止不重置去重記憶。

事件在語音互動開始前即可送入活力計算。沒有交談的客人仍會影響活力。
不需要客人到櫃檯 checkout，不推算店內在場人數，也不新增離店計數。
現有 session 結束與 departure 安全流程仍有其獨立用途。

這是單一 presence 訊號的試作，**不是精確進店或多人計數**：

- 無法區分同時出現的多人，或沒有空畫面就交換的兩個人。
- 同一人離開畫面達重置條件後再出現，會被視為下一次到訪。
- 超過重置時間的遮擋可能造成重算；視野外的客人不會被計入。
- 沿用既有相機生命週期，辨識及啟動等階段仍有觀測空窗，不能當作全天連續客流感測。
- 不新增 MemberID、人臉、embedding、姓名或任何跨畫面身分追蹤資料。

## 活力規則

採單調時間與最近 600 秒的滾動時間窗。事件年齡恰好 600 秒即過期。

| 時間窗內來客事件 | 活力 |
| --- | --- |
| 0–2 | 平穩 calm |
| 3–5 | 開心 happy |
| 6 以上 | 興奮 excited |

無新事件時也要隨舊事件過期降溫，不等下一個客人來才更新。
分級最多只需保留最新 6 筆時間，無需建立營業日客流紀錄或持久化資料。
此有界資料只支援活力分級，不能當作精確來客總數。

活力由 Presentation 映射到既有 Avatar 視覺值；專注聆聽、思考、提醒、
困惑及離線語意優先，不讓人多時的開心表情蓋過互動意圖。事件動畫層
仍保有既有替換與到期行為。UI 不直接接收 Domain 活力型別。

## 預錄迎賓

使用已試聽的 8 段 OpenAI Marin WAV，以 SwiftPM resource bundle 隨 App
提供，不在每次迎賓時重新生成語音。2026-09-17 使用者核准音量校準：
可使用保留原聲線、內容、語速及時長的離線響度校準版本，並於 App bundle
外保留原始檔及重製紀錄；詳見 `audio-loudness-calibration.md`。

| 類別 | 素材 |
| --- | --- |
| 未知客人迎賓 | 01-welcome、02-welcome、03-welcome |
| 已知會員問候 | 04-returning、05-returning、06-returning |
| 道別播放能力 | 07-goodbye、08-goodbye |

迎賓按已知／未知類別及當時活力選句，同類素材不能連續重複。這些是同一
聲線的不同句子；本期沒有重新錄製不同情緒強度的聲音。
道別素材可由播放介面使用，本期不新增自動道別觸發。

本機迎賓啟用時，冷啟動與 standby 啟用都不能再送出用於迎賓的
`response.create`。播放期間的本機音訊不得被麥克風回灌當成客人發言。
播放結束後才接續正常即時對話；重連不重播迎賓。既有工具呼叫、會員資料
授權、登錄同意與後續對話回應保持原有規則。

播放必須回報可觀察的開始、完成與失敗，停止時確實結束等待，舊播放的
callback 或延後取消不能影響下一段音訊。AVFoundation 留在 Infrastructure，
音訊路由與 session activation 由既有音訊組合管理。

本機音檔播放沒有逐次生成語音的 API 費用；後續 Realtime 對話仍會計費。
本期不以單元測試推估實際月帳單，也不新增付費錄音、部署或手機安裝。

## 驗收

1. 持續 presence、短暫遮擋、相機故障、語音失敗重試不會重算同次到訪。
2. 3 秒無人重置，以及 0／2／3／5／6 次分級與逐筆 600 秒過期正確。
3. 沒有語音互動也更新活力；idle 時會降溫。
4. Avatar 映射值合法，優先語意及既有事件層不被覆蓋。
5. 分類選句不混用，且同類不連續；8 段 bundle 資產可追溯至原試聽檔。
   響度校準版本須檢查編碼、時長與峰值，原始檔 hash 保留供驗證。
6. 冷啟動、standby、reconnect 不造成雙重迎賓，預錄播放不開放輸入回灌。
7. 完成、失敗、取消、過期 callback 與新 session 的生命週期都有測試。
8. 執行 `swift test`、Simulator App 測試與指定的無簽章 Simulator build。

實機仍需確認音量、路由、播放銜接、台灣國語聽感及真實相機遮擋表現。
