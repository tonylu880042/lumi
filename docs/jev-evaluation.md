# Jev 對 Lumi 的適用性評估

評估日期：2026-09-17。僅完成文件與架構評估，未接入服務、呼叫付費 API 或傳送會員資料。

## 建議

值得做小範圍意圖分類實驗；目前不建議用它取代 Lumi 的 Realtime 語音對話。
最有價值的方向是判斷客人想結束聊天、是否有適用的預錄回答，以及何時交回現有語音模型。
這是根據公開介面與本專案架構的推論，尚非 Lumi 的實測結果。

Jev 提供結構化選擇與評分，不生成自由文字；官方目前仍列為 early access。
公告價格為每百萬輸入 token US$0.042，輸出免費；其速度與節費倍數是廠商特定測試結果，不能直接當成 Lumi 的預期。
[官方介紹](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## 適用範圍

| Lumi 工作 | 建議 | 原因 |
| --- | --- | --- |
| 分辨真正道別與「先別說再見」 | 適合評估 | 可定義有限的意圖選項並保留不確定結果 |
| 從核准的預錄句子選擇回答 | 最有節費潛力 | 命中時可省掉該次即時語音生成 |
| 判斷轉交教練或繼續回答 | 可評估 | 只提供路由建議，仍由 Application 決定行為 |
| 自然聊天、發聲、維持 Marin 音色 | 不能直接替換 | 公開 API 是狀態／文字判斷，沒有語音輸入輸出介面 |
| 到訪計數、情緒級距 | 維持現有程式 | 已有確定規則，無須付費模型判斷 |
| 臉部身分、會員授權、硬體操作 | 不交給 Jev | 保留現有辨識、授權與 Application 控制邊界 |

官方 HTTP API 接受 `state` 與 `questions`，提供 Choice、Score、Noul 等結果；可透過現有 Broker 封裝，不需要 iOS 直接保存新供應商金鑰。
[API 文件](https://docs.typesafe.ai/api)

## 與現有系統的差異

目前 Lumi 由 `OpenAIRealtimeAdapter` 處理語音，並透過 `end_conversation` 工具取得道別意圖；
`RecordedGreetingCoordinator` 播放已打包音檔，`AssistantSessionCoordinator` 負責結束會話。
因此單純在旁邊多呼叫一次 Jev，會增加一次服務請求，並不自動減少原本語音費用。

真正可測試的下一階段流程是：

客人語音 → 語音轉文字 → Broker / Jev → Application 驗證決策 → 預錄回答或 Realtime 回答。

必須讓命中的預錄回答取代即時生成，才有可計算的節費。現有 Realtime 設定沒有獨立提供此用途的輸入逐字稿；
語音轉文字、回合交接與備援都需要新增設計及成本。Jev 本身不發聲，因此可以繼續使用現在的 Marin 預錄內容。
網路往返與語音轉文字也可能增加延遲；要在台灣網路實測，不能只引用廠商延遲。

## 每月分類費試算

沿用每天 300 人次、每週六天，平均每月 26 個營業日：7,800 人次。
假設每人呼叫兩次，每次總輸入為 500–1,000 token（包含指令、選項說明及上下文）：

| 項目 | 較短輸入 | 較長輸入 |
| --- | ---: | ---: |
| 每月呼叫 | 15,600 | 15,600 |
| 每月輸入 token | 7,800,000 | 15,600,000 |
| Jev 分類費 | US$0.3276 | US$0.6552 |

計算：人次 × 每人呼叫數 × 每次輸入 token ÷ 1,000,000 × 0.042。
約 US$0.33–0.66／月，僅為分類費，不是 Lumi 總帳單；未含語音辨識、剩餘 Realtime 對話、Broker、稅費及其他方案限制。
價格依上述公告，採用前應確認 early access 的實際帳務條件。

## 建議實驗與判定方式

先建立約 100–200 則人工標註、無會員資料的台灣華語案例，包含道別、否定、引用、提問、模糊意圖與辨識錯字。
比較現有流程與 Jev 的誤結束率、漏判率、預錄回答命中率、台灣端 p50/p95 延遲及每次實際 token。
這個樣本數只是起始實驗建議，不是可直接上線的驗收門檻。

Jev 的 confidence 來自預測分布，不能視為該判斷必然正確。
特別要優先避免把「還有問題」誤判成道別；信心門檻須由測試資料與產品容錯要求共同決定。
低信心、逾時或服務錯誤時保留原本對話能力，不強制結束。
[Confidence 說明](https://docs.typesafe.ai/confidence)

官方公開評測以其他強模型的共識作為參考，尚不能證明店內台灣華語的收尾辨識表現。
[評測方法與案例](https://evals.typesafe.ai/)

若之後進入真實流量試驗，再確認 API 可用資格、資料保留地點與期限、服務承諾及價格。
隱私政策表示不使用 Input 訓練／微調模型，但這不等同零保留；實驗應從合成、去識別文字開始。
[隱私政策](https://typesafe.ai/legal/privacy-policy)

結論：先把目前預錄迎賓與自然收尾驗證穩定，再評估「Jev 選擇預錄回答」；本次沒有改動正式語音路徑以接入 Jev。
