## 1. 目標與已確認範圍

會員下次與 Lumi 見面時，Lumi 能接續之前的互動，分辨今天是否見過、
最近是否經常見面、是否久未見，並回應會員當下告知的運動狀態。

使用者已確認：

- 長期目標是整合正式到店／運動紀錄。
- 現階段無法連接運動紀錄資料庫，先規劃「見面記憶＋會員口頭告知」。
- 2026-09-18 已要求交由 Luna 開發，並核准第 7 節規則；未要求實機部署。

首輪在單一裝置上，以已辨識的本機 MemberID 保存有限的結構化事件。
須另行說明用途並取得記憶同意，保存最近 90 天事件，提供管理者清除與停用入口。
不能從原有臉部登錄同意直接推定已同意新增的互動歷史保存用途。

成功的體驗是「記得與妳見面、聽懂妳說的狀況」，不能把這些紀錄當成正式出席率。

## 2. 現有基礎與限制

| 現有元件 | 可沿用部分 | 本功能需要補足 |
| --- | --- | --- |
| LocalMemberDataStore / SQLiteMemberDataStore | 本機會員與時間事件儲存 | 尚無自動見面寫入流程、事件去重與本功能的資料生命週期 |
| MemberVisitSummary / VisitFrequencyBand | 次數與最後來訪時間的基本模型 | 現有 COUNT(*) 是事件數，不能直接當不同見面日；既有分組不是本需求已批准的頻率門檻 |
| AssistantSessionCoordinator | 本機已知會員與 session 生命週期 | 記憶讀取、有效事件寫入、取消與重連的一致性 |
| VoiceToolCallRouter | 工具綁定當前 MemberID、重複 call 處理 | 本人告知事件的受控寫入與更正 |
| ExerciseSummary / MemberRepository | 未來正式資料的內層入口 | 現在 Debug-Live 是明示的合成測試資料，不能與本機真實互動混用 |
| 錄製迎賓、自然收尾 | 一次迎賓、自然結束、同次停留不重開 | 情境化開場已核准；開發時修訂 ADR-0015 的適用範圍 |

匿名 camera arrival proxy 僅用於 Lumi 的活力表現，不可用來推算某會員到店次數。
既有 visits 表的舊資料若缺乏事件來源，不可直接遷移成「已確認互動」。

## 3. 情境與語意

各情境可以同時成立。情境資料與 AssistantState 分開，無須為每種會員狀況
新增一個 Avatar/session 狀態。

| 情境 | 需要的證據 | 可用語句示意 | 不可推論 |
| --- | --- | --- | --- |
| 今天首次見面 | 今天沒有已確認見面事件 | 「今天也一起加油～」 | 今天第一次進店、人生第一次來店 |
| 今天已見過 | 今天較早有見面事件 | 「又見面啦～」 | 已運動完或現在要離店 |
| 最近常見 | 指定期間內多個不同見面日 | 「最近常常看到妳耶！」 | 正式運動次數、運動量或過度運動 |
| 久未見 | 有可信的較早紀錄且達門檻 | 「好久沒見到妳了，最近過得怎麼樣？」 | 生病、受傷、沒運動或生活出問題 |
| 準備運動 | 會員表示現在準備運動 | 「好呀，今天也一起加油！」 | 已開始或已完成運動 |
| 剛運動完 | 會員當下明確說自己剛完成 | 「辛苦啦～今天運動感覺如何？」 | 儀器驗證的完成時間或成績 |
| 今天已運動 | 會員明確說今天已完成 | 「妳說今天已經運動過了，辛苦啦！」 | 現在才剛完成 |
| 無足夠資料 | 初次記錄、過期、清除或讀取失敗 | 一般親切招呼 | 「妳很久沒來」或把無資料當零次 |

示意語句不是每次固定追問的腳本；維持現有簡短交流、不刻意延長對話的原則。
旁邊多人或隱私條件不明時，不主動播報個人歷史或運動資訊。

## 4. 建議資料設計（概念，非定稿 API）

建議採結構化事件加上即時計算的摘要，沿用 SQLite 基礎，不新增向量資料庫、
通用長期聊天記憶框架或完整逐字稿儲存。

每筆事件在本機關聯 MemberID，並記錄：

- 事件 ID 與本機互動 ID：防止同一次互動因重連、重送或重啟重複寫入。
- 事件種類：完成見面、有效對話回應、本人告知運動狀態、更正／撤回。
- 記錄時間 recordedAt；必要時另記日期語意，不能把說話時間當實際運動完成時間。
- 來源：Lumi 觀察／本人告知；未來正式資料另有來源，不覆蓋成同一事實。
- 運動告知的有限值：準備運動、剛完成、今天完成；不儲存任意健康文字。
- 有效範圍與撤回關聯：用來讓過期或被更正的狀態停止影響對話。

摘要由仍有效且獲准使用的事件推導：上次見面、上次有效對話、今天是否見過、
最近不同見面日數、本人告知的當前／今日運動情境。
事件留存期限與情境有效期限不同；事件尚未刪除不代表「剛完成」仍然有效。

時間以絕對時間保存，日界線使用 Asia/Taipei 的門店曆日。
近 7 天是包含今天的 7 個門店日，與本週出席統計不同。
錯誤的未來時間或時鐘倒退不能產生負間隔、虛構常見或久未見結論。

## 5. 建議流程與一致性

1. 現有辨識流程確認 known(MemberID)，檢查本功能的記憶使用／保存同意。
2. 讀取本次事件之前的歷史快照，計算可用情境；無資料與讀取錯誤分開處理。
3. 經隱私檢查後選擇一個主要互動重點，避免一次列舉所有歷史狀態。
4. 在核准的見面完成時點寫入一次事件。不能先更新 lastSeen 再計算久未見。
5. 會員有說話時，可獨立更新有效對話紀錄；不能把 Lumi 自己的音檔回音算成回應。
6. 若會員明確告知自己現在／今天的運動狀態，模型提出受控工具請求。
   Application 驗證當前 session、會員綁定、同意、列舉參數及重複請求後才寫入。
7. 寫入成功才說已記住；寫入失敗仍可回應當下內容，不宣稱記憶已保存。
8. 結束時沿用現有一次道別與 presence rearm。下一位會員不得接到前一位資料。

重連必須沿用同次互動的去重鍵；即使模型換一個 call ID 重述相同內容，
也不能重複增加見面日或有效運動告知。已結束 session 的遲到回呼不可寫入。
撤回、清除或更正發生時，先前快照與待處理寫入也必須失效，避免資料被寫回。

模型理解語意，Application 限制可寫入的資料。以下不能因關鍵字而記成剛完成：
「我還沒運動」「昨天運動完」「她剛運動完」「如果我運動完」以及引用他人的話。
「我剛才說錯了」需要更正既有紀錄，不能增加第二次完成運動。
無法確定時間或主詞時，不持久寫入；必要時簡短確認，不為保存資料而固定追問。

## 6. 架構與既有契約的變更點

依現有 Clean Architecture：

- Domain：事件與來源值型別、見面頻率及有效期規則，注入時間／日曆條件做純邏輯判斷。
- Application：記憶讀寫 Port、載入摘要／記錄見面／記錄與更正本人告知／清除記憶 Use Cases；
  Coordinator 保持唯一 session 管理者，工具綁定當前已知會員。
- Infrastructure：SQLite schema migration、原子去重與刪除、語音工具參數映射。
- Presentation：把核准情境轉成自身的顯示值與 AvatarEventCommand；UI 不接 Domain 型別。
- App composition：注入存放區與 Use Cases，按確認後的試用範圍啟用。

工具不得接受模型提供的 MemberID、姓名查找、任意 SQL、任意時間戳或自由文字記憶。
來源標籤與時間由應用程式依核准語意產生，不由模型聲稱是正式資料。
Unknown 可以自然回應當下話語，但沒有會員歷史查詢／持久寫入的能力。
Unknown 完成登錄並取得獨立記憶同意後，於下一次已知會員 session 啟用，
不能偷偷繼承登錄前的片段。

現有 ADR-0011 採已知會員、按需查詢；本次已核准為個人化主動開場事先讀取
已同意會員的最小互動摘要。開發時新增 ADR 記錄這項目的限定的變更，
不擴張既有正式／合成運動資料查詢權限。
模型只接收允許的語意摘要與來源，不接整包事件、會員 ID、臉部資料或精確歷史時間。
Broker 繼續不接會員資料。

錄製迎賓整合已核准：有核准情境時以一次情境化開場取代一般錄音；無情境時
沿用錄音。需修訂 ADR-0015，並測試麥克風、輸出互斥與取消，避免兩段連續迎賓。

## 7. 已核准的產品規則（2026-09-18）

核准依據：使用者在完整設定確認選項後回覆「可以 但要此規則記錄在文件中」。
以下採用先前提案的建議方案，作為 Luna 開發與測試的共同依據。

| 規則 | 已核准行為 |
| --- | --- |
| 一次見面的起點 | 辨識結果為 known 且完成招呼即記一次見面，不要求會員開口。招呼未完成不記；一天多次僅算一個見面日。 |
| 最近常見 | 包含今天的近 7 個門店日內，已完成見面的不同日期至少 3 天。重連、重播、重複工具事件不增加次數。 |
| 久未見 | 有未過期的上次見面紀錄，且距該門店日期滿 14 天。開場使用本次寫入之前的歷史快照，不能先覆寫上次時間。 |
| 留存與同意 | 告知用途並另取得記憶同意後，在本機保存最近 90 天的結構化事件，提供清除。無資料、超期或讀取失敗時不推測。臉部登錄同意不等同本功能同意。 |
| 日界線 | Asia/Taipei 的門店曆日；不隨裝置的顯示時區切換。 |
| 本人告知有效範圍 | 「剛運動完／準備運動」只影響當次 session；明確「今天完成」可影響當日後續對話，跨日失效。不能將告知時間當精確完成時間。 |
| 明確／模糊告知 | 在有效同意及當前已知會員 session 下，明確本人告知可直接記錄；模糊內容不記，必要時簡短確認。否定、引用、別人的事與假設不當成自己的完成紀錄。 |
| 多情境互動 | 先回應會員當下所說，再選今天再見／久未見／最近常見中的一個重點，不固定追問或一次列舉所有狀態。 |
| 開場方式 | 有可用且允許透露的情境時生成一次個人化開場，取代一般錄音；無情境時沿用錄音。不可連播兩次迎賓。 |
| 刪除／撤回入口 | 首輪提供管理者可操作的會員記憶清除與停用；語音刪除入口不在本輪範圍。清除不得刪除非本功能的臉部資料或會員身份。 |
| 新登錄會員 | 完成獨立記憶同意後，下一次已知會員 session 才啟用；不回填未知身份期間的對話。 |
| 首輪發布範圍 | Debug-Live 單機試用，與合成運動資料隔離；本輪不啟用正式版、不串正式資料庫、不部署實機。 |

時點一致性：開場只使用先前已完成的見面，不能預先把尚未完成的這次招呼算入
「最近常見」；招呼完成後的新摘要才包含本次日期。「今天已見過」同樣以進入
本次互動前的紀錄判斷。所有情境只描述與 Lumi 見面，不得說成實際到店或運動次數。

超過保留期後沒有資料，不得宣稱「首次來店」或精確多久沒見；清除也要清掉
衍生摘要、個人事件去重關聯及快取，並使正在進行的舊寫入失效。
不保存完整逐字稿、原始音訊、任意健康故事；不新增雲端同步。
備份排除與資料清除須在持久化實作與測試中落實，移機不隱含記憶移轉。

已核准規則變更時，必須同步更新本節、相關 ADR 及測試；新增且影響 UX、
隱私或資料語意的未決事項仍依 AGENTS.md 向產品負責人確認。

## 8. 日後升級正式運動紀錄

保留既有 MemberRepository 作為正式資料入口，等 endpoint、身分對應、授權、
時區、資料新鮮度與錯誤契約核准後，新增正式 Adapter。

- 本機生成的 MemberID 不等於 Curves 會員帳號，需經核准的綁定方式，不以同名匹配。
- Lumi 見面、本人告知、正式到店與正式完成運動各保留自己的來源與時間語意。
- 不將過去見面日回填成正式運動次數，不將本人告知回寫成正式完成紀錄。
- 正式資料有延遲時，「尚無紀錄」不自動否定剛才的本人告知；衝突呈現與優先規則另定。
- 未來可以把「最近常見妳」擴充為有正式證據的「最近運動很規律」，語音與 Avatar
  不必知道外部 API 的 DTO 或驗證方式。

第一版只保留足夠來源資訊與架構邊界，不預先製作同步引擎或猜測正式 API。

## 10. 測試與驗收

使用專案現有 Swift Testing／XCTest，測試置於各層對應 Tests 目錄與 App/LumiAppTests。
Domain 測試使用可控制的時間，不依賴 Simulator、網路、Vision 或 OpenAI。
每個新增 Use Case、生命週期分支和資料有效性轉換都要先有失敗測試。

依第 7 節至少驗收：

1. 同日三次互動：可保留三筆合法互動，最近見面日數只能增加一天。
2. 晚上到隔天、門檻前後與期間邊界：按核准門店時區穩定分類。
3. 久未見會員：本次寫入不覆蓋判斷所需的上次時間。
4. App 重啟後：已同意且未過期的記憶仍在；超期／已清除／未同意不再使用。
5. Unknown、另一會員、已結束 session：不能讀寫前一位會員的紀錄。
6. 重複 call、換 call ID 重述、連線重試：不重複記錄同一事件；一段停留不重開迎賓。
7. 說「剛完成」、否定、昨天、她、假設、引用及更正：依核准語意處理，不虛構日期。
8. 「剛完成」過期後不再說剛完成；當日告知在跨日後不再稱為今天完成。
9. SQLite 讀寫失敗：維持一般對話；不宣稱零次、不假裝已記住。
10. 清除／撤回與正在進行的寫入競爭：刪除後不被遲到回呼重新建立。
11. 生成開場、錄音、重連、道別互斥：無雙重迎賓、無音檔回音誤寫入。
12. 工具結果、提示與診斷：無會員 ID、完整事件列表、逐字稿、臉部資料或合成真實混用。

提示字串測試不能證明模型理解語意；真實中文說法需 Live 人工驗收。

## 11. 專案結構、風格與邊界

程式：Sources/LumiDomain、LumiApplication、LumiInfrastructure、LumiPresentation、LumiUI。
組裝：App/LumiApp/Sources。測試：Tests/<對應層>Tests 與 App/LumiAppTests。
規格：docs；核准後的架構決策：docs/decisions。

沿用現有明確、具型別、async throws 的 Port 風格，例如既有介面：

```swift
public protocol LocalMemberDataStore: Sendable {
    func saveMember(_ member: Member) async throws
    func member(for id: MemberID) async throws -> Member?
    func recordVisit(memberID: MemberID, at arrival: Date) async throws
    func visitSummary(for memberID: MemberID, since startDate: Date) async throws -> MemberVisitSummary
}
```

這是風格參照，非決定直接以 recordVisit 承載新互動語意。

- Always：依來源陳述事實、已知會員的本機綁定、最小資訊、TDD、可取消且可去重的寫入。
- Ask first：對第 7 節已核准規則的產品變更，或超出既定範圍的新 UX、隱私、資料語意。
- Never：以見面代替運動、以姓名串接正式會員、保存完整音訊／逐字稿作此功能記憶、
  未知身份查詢會員歷史、LLM 直寫資料庫／控制硬體、UI 匯入 Domain。

## 14. 首輪實作與驗證結果（2026-09-20）

已完成 Debug-Live 單機範圍：

- Domain 依 Asia/Taipei 門店曆日計算今天已見、近 7 日至少 3 個見面日、滿 14 日久未見與 90 日留存。
- Application 以當前 known MemberID、獨立同意與 session revision 綁定讀寫；完成招呼才記見面，Unknown、未同意、舊 session 與遲到回呼均失效。
- 本人告知只接受 `preparing`、`justCompleted`、`completedToday` 三種值；前兩者只留在 session，後者只保留到當日，並支援更正／撤回與 not-found 結果。
- Infrastructure 使用獨立的 `MemberInteractionMemory.sqlite` 與專用目錄，不與身分、臉部 embedding 或既有 visit DB 混存；目錄排除備份，SQLite 寫入、清除、停用、更正與 prune 均以 revision 防止舊寫入復活。
- 2026-10-06 維護修正：迎賓讀取只清理當前會員，沒有過期事件時不開寫入交易；實際刪除仍與該會員 revision 遞增在同一交易完成。啟動時的 `pruneExpired` 保留全庫清理；其他會員的過期資料由全庫維護或本人下次讀取刪除，未新增定期排程，90 日截止規則不變。詳見 ADR-0017 的 maintenance amendment。
- 管理入口只讀本機已完成登錄的 `spoken_label`，可分別啟用、停用或清除互動記憶；不以同名、舊會員表或原始 MemberID 當顯示名稱，清除不刪身分資料。
- Realtime 只收到最小語意摘要；情境開場只完成一次，`preparing`／`justCompleted` 在跨日重連後仍只限本 session，`completedToday` 在 Asia/Taipei 跨日、時鐘回撥、一般重連、standby promotion 與未斷線的下一個事件都會失效，且不重開迎賓。來源時間只留在本機有效性判斷，不進入 provider prompt 或 wire payload。Debug-Live 的合成每週運動摘要工具已停用，避免與真實互動記憶混用。
